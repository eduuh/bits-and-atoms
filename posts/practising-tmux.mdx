I checked my tmux key log and found 334 presses of the project picker, while searchable scrollback, pane rearrangement and the buffer picker had little or no recorded shortcut use.

Same picker. Again.

I've built a terminal workflow around tmux, but installing a feature doesn't make it a habit. I'd rather practise five things with fake output than memorise another shortcut table.

<Callout type="warning" title="Use a spare window">
  These exercises don't need a build, a running agent or a real error. Leave those panes alone.
</Callout>

## Before touching the keyboard

This walkthrough uses my live configuration: <Kbd>Ctrl+Space</Kbd> is the prefix, copy mode uses vi keys, and tmux reports version 3.8. When I write "prefix, Space", press <Kbd>Ctrl+Space</Kbd>, release it, then press <Kbd>Space</Kbd>.

Two separate presses.

Check your own server first:

```bash
tmux -V
tmux show-options -gv prefix
tmux show-options -gwv mode-keys
tmux list-keys -T prefix
```

These show the version, prefix, copy-mode keys and current bindings.

Searching scrollback and moving panes are native tmux features, but a reader with a stock configuration won't get my shortcuts just by installing the same tmux version.

| Exercise | What it needs |
|----------|---------------|
| Search output | Native copy mode, with vi keys |
| Extract text | The extrakto or tmux-fingers plugin and its binding |
| Rearrange panes | Native tmux commands, with my split and join bindings |
| Float a shell | The native floating-pane commands present on my server |
| Recover copies | Native tmux buffers |

In my configuration, prefix then <Kbd>w</Kbd> opens a new window in the current directory. Do that in the blog checkout.

Fill it with something harmless:

```bash
printf '%s\n' \
  'TMUX-PRACTICE: pretend build failed' \
  'file=/tmp/tmux-practice/example.txt' \
  'url=https://example.com/tmux-practice' \
  'request_id=practice-4821'
seq 1 100
```

This prints searchable markers followed by enough numbered lines to push them into scrollback. It doesn't create the named file or contact the URL.

The demo below replays only the four marker lines. It doesn't run commands in your terminal.

## 1. Find the line without scrolling

Press prefix, then <Kbd>Space</Kbd>. You're in copy mode.

Type `/TMUX-PRACTICE` and press <Kbd>Enter</Kbd>. Use <Kbd>n</Kbd> for the next match and <Kbd>Shift+N</Kbd> to search in the opposite direction. If the first search doesn't find it, try `?TMUX-PRACTICE` to search backwards.

Now search for `request_id`. Move the cursor to the value, press <Kbd>v</Kbd> to start selecting, and use the movement keys to cover `practice-4821`. Press <Kbd>y</Kbd> to copy and leave copy mode.

No dragging.

<Callout type="success" title="Checkpoint">
  Find and copy the ID without dragging the scrollbar.
</Callout>

<Callout type="warning" title="The key table matters">
  To leave copy mode without copying, press <Kbd>q</Kbd>. That's a copy-mode key, not an instruction to press prefix then <Kbd>q</Kbd>. The same key can do something different outside copy mode.
</Callout>

## 2. Extract the text instead

My prefix then <Kbd>u</Kbd> opens extrakto, which fuzzy-searches retained pane output.

Search for `practice-4821`. <Kbd>Enter</Kbd> copies the selected text. <Kbd>Tab</Kbd> inserts it into the pane without submitting a command. Only try insertion in the spare shell, at an empty prompt.

For text already on screen, print the sample again without the numbered lines, then press prefix and <Kbd>Shift+F</Kbd> to have tmux-fingers label things such as URLs and paths with letter hints.

Press a hint. It copies the text.

Don't install both plugins just for this exercise. Start with whichever is already available.

<Callout type="success" title="Checkpoint">
  Copy the fake path or ID without selecting it character by character.
</Callout>

<mark>Search reaches into scrollback; hints work on visible output.</mark>

## 3. Move a running pane

Press prefix then <Kbd>v</Kbd> to split right in my configuration. Run this in the new pane:

```bash
while :; do date '+%H:%M:%S'; sleep 2; done
```

This prints the time until you stop it with <Kbd>Ctrl+C</Kbd>.

While the clock is running, press prefix then <Kbd>!</Kbd>. tmux breaks that pane into its own window. The command stays running.

Return to the original practice window using prefix then <Kbd>Ctrl+J</Kbd>, the native session tree, then press prefix and <Kbd>@</Kbd> and choose the clock window to pull its pane alongside yours.

Try prefix then <Kbd>z</Kbd> to zoom the clock pane. Repeat to unzoom. Prefix then <Kbd>Shift+arrow</Kbd> resizes it in my configuration.

<Callout type="success" title="Checkpoint">
  Check that the clock continues through the move. You changed its layout, not its process.
</Callout>

Stop the clock with <Kbd>Ctrl+C</Kbd> when you're done.

## 4. Float a shell, then tile it

My live server has a prefix then <Kbd>Shift+Tab</Kbd> binding that creates a floating pane. Check yours:

```bash
tmux list-keys -T prefix BTab
tmux list-commands | grep '^new-pane '
```

These inspect the binding and command without opening anything.

Press the shortcut if it's present. Type this in the floating shell:

```bash
printf '%s\n' 'This is a persistent shell, not a disposable popup.'
```

It prints a marker you can recognise after moving the pane.

On my server, right-clicking the pane opens a menu with a Tile action. Choose it.

<mark>Same shell, different layout.</mark>

The marker remains in its history, and the pane menu can float it again.

<Callout type="success" title="Checkpoint">
  Float and tile the shell without starting a replacement shell.
</Callout>

I wouldn't teach this as a shortcut everyone has. The floating-pane exercise depends on the commands and bindings available on the server running tmux, which may be the remote machine.

## 5. Recover an earlier copy

tmux buffers and the system clipboard aren't the same thing. Make two clearly named practice buffers:

```bash
tmux set-buffer -b practice-first 'practice-4821'
tmux set-buffer -b practice-second '/tmp/tmux-practice/example.txt'
```

This creates two tmux buffers without changing the system clipboard. If you've used these names before, it replaces those practice buffers.

Press prefix then <Kbd>=</Kbd> to open the buffer picker on my server. Choose the first buffer and paste it into an empty shell prompt. You should get the ID, even though you created the path buffer afterwards.

Don't press <Kbd>Enter</Kbd> at the shell prompt. Clear the inserted text with <Kbd>Ctrl+C</Kbd>.

<Callout type="success" title="Checkpoint">
  Recover `practice-4821` after copying the path. The older buffer is still available.
</Callout>

Remove only the practice buffers:

```bash
tmux delete-buffer -b practice-first
tmux delete-buffer -b practice-second
```

This leaves your other tmux buffers alone.

## One combined exercise

Print the sample output again. Without mouse selection:

1. Find the pretend failure in scrollback.
2. Extract the request ID.
3. Split a shell, run the clock, and move it into another window and back.
4. Float a shell and tile that same shell again.
5. Create the two practice buffers and recover the older one.

Stop the clock and remove the practice buffers afterwards. Leave the practice window open if you want another attempt.

The test is <mark>doing it twice</mark>, with this page closed for the second attempt.

## What this doesn't prove

My usage log had gaps and counted mouse actions separately, so a missing shortcut count doesn't prove I never used a feature through a menu, a script or another binding.

The live bindings differed from the repository's cheat-sheet, too. Inspect the active server before copying a shortcut, especially a close or kill shortcut. Plugins and clipboard behaviour can differ across local and remote tmux.

These exercises use fake output on purpose. Once I can repeat them without checking the keys, I'll try them in a real debugging session.
